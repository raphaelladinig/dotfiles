# Global instructions

Treat this file as global defaults. When project-level `AGENTS.md` instructions
conflict with this file, follow the project-level instructions.

## Commit messages

Use Conventional Commits by default unless the repository explicitly requires
another format. Write subjects as `type(scope): description`; the scope is
optional. Mark breaking changes with `!` before the colon or a
`BREAKING CHANGE:` footer.

## Comments and documentation

Keep comments minimal. Add a brief comment only to explain non-obvious intent
or constraints that the code itself cannot convey.

Keep comments and documentation in sync with the code in the same change.
Update relevant `AGENTS.md` files whenever changes affect the instructions they
contain, including workflows, commands, project structure, and conventions.
Before finishing, check affected guidance and correct or remove stale content.

## Writing style

Apply these defaults to all prose, including replies, documentation, and commit
messages. Preserve meaning and match the intended tone when editing.

- Use plain words, active voice, and concrete facts. Name the mechanism, source,
  or measured result instead of relying on jargon or vague claims.
- Cut filler, hype, unnecessary hedging, canned greetings, flattery, and generic
  conclusions. Keep uncertainty when the evidence warrants it.
- State the point directly. Avoid formulaic contrasts, forced groups of three,
  and changing terms just for variety.
- Keep one idea per sentence and split dense sentences. Vary sentence length
  and express a reasoned view when useful. Use first person when it fits.
- Separate thoughts with periods or commas. Reserve colons for lists and
  examples.
- Keep formatting sparse. Use sentence case headings and straight quotes.
  Prefer prose when a list adds no clarity. Skip decorative emojis and bold
  labels that repeat the text.
- Before sending, reread for generic or mechanical phrasing. Rewrite anything
  that adds no concrete information or sounds unnatural.
